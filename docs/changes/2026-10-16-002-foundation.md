# 2026-10-16 基础执行协议与独立业务判定

## 目标

先实现能够在本地验证的核心逻辑，为真实 GUI 与训练数据接入保留明确接口。

## 改动

- `contracts/action.schema.json` 与 TypeScript 协议：限定动作、坐标和参数，拒绝额外命令与非有限数值。
- `geometry.ts`：处理裁剪、旋转、屏幕边缘和过期观察。
- `oracle.ts`：整数分金额判定、证据归属、GUI 前置步骤，以及 PASS/PRODUCT_FAIL/AGENT_BLOCKED/INCONCLUSIVE 区分。
- `runner.ts`：动作与时间预算、模型输入隔离、独立 oracle、清理和基础设施故障分类。
- `evaluate.ts`：保留所有预定运行作分母，防止三次只成功一次却计作全部检出。
- `report.ts`：保存 JSON 和转义的 HTML，拒绝覆盖同 run_id 的历史报告。
- CLI 提供 `demo` 与 `doctor`；CI 在推送或 PR 时执行本地基础检查。

## 边界与决定

- Ruling: 先推进可独立验证的协议与判定模块，真实 Task 1 联调待设备/模型条件满足后继续；这改变实施先后顺序，不改变验收要求。代价是 SDK 接入时可能需要调整动作适配器。
- 尚未实现实际 Midscene/ADB driver、设备租约、有限自愈、完整多语言 schema 生成、版本化训练轨迹、用例生成、SFT 或 GPU 实验。
- 模拟策略为确定性动作夹具，不是训练后的模型。当前报告不能用于宣称真实 GUI 成功率。
